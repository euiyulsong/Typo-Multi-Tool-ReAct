## 오타 교정 × Multi-tool 호출 실험 결과

### 실험 설정

- 모델: `gpt-6-luna`
- 평가: 독립적인 multi-tool 요청 100개
  - 일반 단어 오타(`intent`): 50개
  - 도시명 오타(`entity`): 50개
- 입력 조건: clean / raw / LLM 교정 / term 교정
- 실행 방식:
  - **One-shot:** 한 번의 agent 응답에서 여러 tool call 생성 후 실행.
  - **ReAct:** tool 결과·오류를 받아 후속 호출.
- 지연 시간은 앞단 교정 비용을 포함.
- `all`과 `parallel`은 동일한 문항을 집계하므로 아래에서는 중복 제거.

### 전체 결과

| 방식 | 입력 | 성공률 | 최초 호출 F1 | Tool F1 | Call Exact | Argument F1 | 평균 지연 |
|---|---|---:|---:|---:|---:|---:|---:|
| One-shot | clean | 100% | 1.000 | 1.000 | 1.000 | 1.000 | 2.58초 |
| One-shot | raw | 51% | 0.529 | 1.000 | 0.510 | 0.529 | 2.54초 |
| One-shot | LLM 교정 | **90%** | **0.934** | 1.000 | **0.900** | **0.934** | 4.68초 |
| One-shot | term 교정 | 70% | 0.770 | 1.000 | 0.700 | 0.770 | 2.55초 |
| ReAct | clean | 100% | 1.000 | 1.000 | 1.000 | 1.000 | 2.51초 |
| ReAct | raw | 53% | 0.515 | 1.000 | 0.500 | 0.554 | 3.86초 |
| ReAct | LLM 교정 | **88%** | **0.917** | 1.000 | **0.880** | **0.917** | 5.22초 |
| ReAct | term 교정 | 71% | 0.776 | 1.000 | 0.710 | 0.782 | 3.32초 |

오타 입력 조건 중 **LLM 교정 → One-shot이 가장 높은 성공률과 Argument F1**을 기록했다. Term 교정은 raw와 비슷한 One-shot 지연으로 성공률을 높였다.

### 오타 유형별 결과

| 방식 | 입력 | 일반 단어 성공률 | 일반 단어 Argument F1 | 도시명 성공률 | 도시명 Argument F1 |
|---|---|---:|---:|---:|---:|
| One-shot | clean | 100% | 1.000 | 100% | 1.000 |
| One-shot | raw | 98% | 0.995 | 4% | 0.062 |
| One-shot | LLM 교정 | **100%** | **1.000** | **80%** | **0.868** |
| One-shot | term 교정 | 98% | 0.995 | 42% | 0.545 |
| ReAct | clean | 100% | 1.000 | 100% | 1.000 |
| ReAct | raw | 98% | 0.995 | 8% | 0.114 |
| ReAct | LLM 교정 | **100%** | **1.000** | **76%** | **0.835** |
| ReAct | term 교정 | 98% | 0.995 | 44% | 0.570 |

- **일반 단어 오타:** raw도 49/50개 성공했다. LLM 교정은 50/50개로 개선했지만 지연이 추가됐다.
- **도시명 오타:** raw 성공률은 One-shot 4%, ReAct 8%로 크게 낮았다. LLM 교정 후 각각 80%, 76%로 개선됐다.
- 전체 성능 차이는 주로 **도시명 오타 처리**에서 발생했다.

### 교정 효과: Raw 대비

| 방식 | 교정 | 전체 성공률 변화 | 도시명 성공률 변화 | 전체 평균 지연 변화 |
|---|---|---:|---:|---:|
| One-shot | LLM | **+39%p** | **+76%p** | +2.14초 |
| One-shot | term | +19%p | +38%p | +0.01초 |
| ReAct | LLM | **+35%p** | **+68%p** | +1.36초 |
| ReAct | term | +18%p | +36%p | −0.54초 |

ReAct에서 term 교정은 성공률을 높이면서 전체 지연도 줄였다. 오류 후 추가 호출이 줄었을 가능성이 있지만, 원인 확인에는 호출 횟수와 trace 분석이 필요하다.

### ReAct 효과: One-shot 대비

| 입력 | 성공률 변화 | Argument F1 변화 | 평균 지연 변화 |
|---|---:|---:|---:|
| clean | 0%p | 0.000 | −0.07초 |
| raw | +2%p | +0.025 | +1.32초 |
| LLM 교정 | −2%p | −0.017 | +0.54초 |
| term 교정 | +1%p | +0.012 | +0.77초 |

이번 독립 multi-tool 문항에서는 ReAct의 성공률 개선이 작았다. LLM 교정 조건에서는 One-shot이 성공률과 지연 모두 우세했다. 1~2문항 차이이므로 반복 평가와 paired 분석 없이 일반적인 우열로 단정하지 않는다.

### 지표 해석

- 모든 조건의 **Tool F1은 1.000**이었다. Tool 종류 선택은 유지됐고, 실패는 주로 argument 구성과 실행 완료에서 발생했다.
- Tool F1은 tool 종류 집합 기준이므로 호출 횟수·중복·argument 정확도를 보장하지 않는다.
- ReAct/raw의 성공률은 53%, Call Exact는 50%였다. 일부 작업은 성공했어도 추가·중복·잘못된 호출 때문에 호출 multiset이 정답과 일치하지 않을 수 있다.
- 표의 `errors=0`은 API·교정 형식 오류가 없다는 뜻이다. Tool 실행 오류가 없다는 의미는 아니다.

### 결론

이번 평가에서는 **오타 교정의 효과가 ReAct loop 추가 효과보다 컸다.**

- **정확도 우선:** LLM 교정 → One-shot, 성공률 90%, 평균 4.68초.
- **지연 우선:** Term 교정 → One-shot, 성공률 70%, 평균 2.55초.
- **일반 단어 오타:** raw도 98% 성공으로 추가 교정 이점이 작았다.
- **도시명 오타:** LLM 교정의 개선 폭이 가장 컸다.

결과는 합성 영어의 독립 multi-tool 문항에 한정한다. 순차 의존성 요청, 실제 사용자 오타, 한국어에 대해서는 별도 평가가 필요하다.
