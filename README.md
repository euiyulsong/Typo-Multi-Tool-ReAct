## 오타 교정 × Adaptive Multi-tool 실험 결과

### 실험 설정

- 모델: `gpt-6-luna`
- 독립 multi-tool 요청 100개: 일반 단어 오타 50개, 도시명 오타 50개.
- 입력 조건: clean / raw / LLM 교정 / term 교정.
- **One-shot:** 한 응답에서 tool calls를 생성하고 실행 후 종료.
- **Adaptive:** tool 결과를 받아 `return` 또는 `followup`을 명시적으로 판단.
- 지연은 교정 비용을 포함.
- `all`과 `parallel`은 같은 문항의 중복 집계이므로 아래에서는 제거.

### 전체 결과

| 방식 | 입력 | 성공률 | 최초 호출 F1 | Call Exact | Argument F1 | 평균 지연 |
|---|---|---:|---:|---:|---:|---:|
| One-shot | clean | 100% | 1.000 | 1.000 | 1.000 | 2.68초 |
| One-shot | raw | 53% | 0.541 | 0.530 | 0.541 | 2.71초 |
| One-shot | LLM 교정 | **83%** | **0.885** | **0.830** | **0.885** | 4.85초 |
| One-shot | term 교정 | 71% | 0.776 | 0.710 | 0.776 | 2.71초 |
| Adaptive | clean | 100% | 1.000 | 1.000 | 1.000 | 5.60초 |
| Adaptive | raw | 57% | 0.541 | 0.530 | 0.571 | 5.37초 |
| Adaptive | LLM 교정 | **82%** | **0.881** | **0.820** | **0.881** | 7.93초 |
| Adaptive | term 교정 | 72% | 0.770 | 0.700 | 0.777 | 5.59초 |

모든 조건의 Tool F1은 1.000이었다. Tool 종류 집합은 정확하게 선택했지만, 도시명 등 argument 정확도에서 차이가 발생했다.

오타 입력 조건 중 **LLM 교정 + One-shot이 성공률과 Argument F1에서 가장 높았다.**

### 오타 유형별 결과

| 방식 | 입력 | 일반 단어 성공률 | 도시명 성공률 | 도시명 Argument F1 |
|---|---|---:|---:|---:|
| One-shot | clean | 100% | 100% | 1.000 |
| One-shot | raw | 98% | 8% | 0.087 |
| One-shot | LLM 교정 | 98% | **68%** | **0.775** |
| One-shot | term 교정 | 98% | 44% | 0.557 |
| Adaptive | clean | 100% | 100% | 1.000 |
| Adaptive | raw | 98% | 16% | 0.147 |
| Adaptive | LLM 교정 | **100%** | **64%** | **0.762** |
| Adaptive | term 교정 | 98% | 46% | 0.559 |

- **일반 단어 오타:** raw도 49/50개 성공했다. 교정·후속 호출의 개선 여지가 작았다.
- **도시명 오타:** raw는 One-shot 4/50개, Adaptive 8/50개 성공에 그쳤다.
- LLM 교정 후 도시명 성공률은 One-shot 34/50개, Adaptive 32/50개로 개선됐다.
- 전체 실패와 교정 효과는 주로 도시명 argument에서 발생했다.

### 교정 효과: Raw 대비

| 방식 | 교정 | 전체 성공률 변화 | 도시명 성공률 변화 | 전체 평균 지연 변화 |
|---|---|---:|---:|---:|
| One-shot | LLM | **+30%p** | **+60%p** | +2.14초 |
| One-shot | term | +18%p | +36%p | 0.00초 |
| Adaptive | LLM | **+25%p** | **+48%p** | +2.56초 |
| Adaptive | term | +15%p | +30%p | +0.22초 |

LLM 교정은 정확도 개선 폭이 가장 컸다. Term 교정은 평균 지연 증가가 작으면서 성공률을 개선했다.

### Adaptive 효과: One-shot 대비

| 입력 | 전체 성공률 변화 | 도시명 성공률 변화 | Argument F1 변화 | 평균 지연 변화 |
|---|---:|---:|---:|---:|
| clean | 0%p | 0%p | 0.000 | +2.92초 |
| raw | **+4%p** | **+8%p** | +0.030 | +2.66초 |
| LLM 교정 | −1%p | −4%p | −0.004 | +3.08초 |
| term 교정 | +1%p | +2%p | +0.001 | +2.88초 |

Adaptive/raw에서는 최초 호출 F1이 0.541에서 최종 Argument F1 0.571로 증가했다. 후속 호출을 통한 일부 복구와 일치하는 결과지만, 어떤 문항을 복구했는지는 trace 확인이 필요하다.

LLM 교정 후에는 Adaptive의 추가 정확도 이점이 관찰되지 않았다. 전체 성공률 차이는 1문항이므로 통계적 우열로 단정하지 않는다.

### 성공률과 Call Exact의 차이

Adaptive/raw는 성공률 57%, Call Exact 53%였다. Adaptive/term은 각각 72%, 70%였다.

작업 성공은 필요한 조회를 완료했는지 평가하고, Call Exact는 실제 호출 전체가 정답 multiset과 일치하는지 평가한다. 따라서 잘못된 argument를 수정하거나 중복 호출한 뒤 작업을 완료하면 성공률과 Call Exact가 달라질 수 있다.

### 비용 비교 시 주의점

이번 지연 차이는 추가 tool 호출 비용만 의미하지 않는다.

- One-shot은 tool 실행 직후 종료하며 최종 답변을 생성하지 않는다.
- Adaptive는 결과를 받은 뒤 종료 판단과 답변 생성을 수행한다.
- Adaptive는 `next_action` wrapper를 사용하므로 출력 형식과 토큰 비용도 다르다.

따라서 Adaptive가 약 2.7~3.1초 느렸다는 결과에는 **종료 판단·답변 생성·wrapper 비용**이 함께 포함된다. 동일한 최종 답변 생성 단계를 추가해야 서비스 전체 지연을 더 공정하게 비교할 수 있다.

### 오류와 추가 확인 사항

표의 `errors=0`은 최종적으로 기록된 API·형식 오류가 없었다는 뜻이다. 복구된 결정 형식 오류나 tool 실행 오류까지 0이라는 의미는 아니다.

종료 판단 자체의 품질을 확인하려면 `summary.json`과 trace에서 다음을 함께 확인해야 한다.

- `decision_format_errors`: 결정 형식 오류 횟수.
- `premature_return`: 작업을 충족하지 않은 상태에서 종료한 비율.
- `additional_followup_batches`: 최초 호출 이후 추가 실행 횟수.
- `execution_complete`와 `returned`: 실행 완료와 명시적 종료 여부.
- `tool_errors`: tool 실행 오류 횟수.

### 결론

이번 독립 multi-tool 평가에서는 **앞단 오타 교정의 개선 폭이 Adaptive 반복의 개선 폭보다 컸다.**

- **정확도 우선 후보:** LLM 교정 + One-shot — 성공률 83%, 평균 4.85초.
- **지연 우선 후보:** Term 교정 + One-shot — 성공률 71%, 평균 2.71초.
- **Adaptive/raw:** 일부 도시명 오류 복구는 관찰됐지만 최종 성공률은 57%였다.
- **종료 판단 정책:** 조기 종료율·추가 호출 횟수를 확인한 뒤 효과를 판단해야 한다.

합성 영어의 독립 호출 문항 결과이며, 순차 의존성 요청이나 최종 답변 품질에 대한 결론은 포함하지 않는다.
